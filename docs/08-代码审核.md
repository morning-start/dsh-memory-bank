## 1. 结论

**这个项目的架构判断是对的，协议层的算术是干净的，但「硬保证」大面积只写在注释和文档里。**

四个域交叉核对后，跨文件契约（17 个 RPC 端点的方法名/参数名/返回形状、142 个文案键、十道门门名、四层配置顺序、`readQuotaState` 镜像）**零漂移** —— 历史上那类「漏一条、测试全绿、界面静默不工作」的 bug 没有复现。0.1.1 修过的问题也确实修住了。

真正的缺陷集中在四个模式，且**每一个都能在这个仓库自己的注释里找到同型的历史教训**：

| 模式 | 表现 | 典型 |
|---|---|---|
| **硬保证是软的** | 注释/文档写「永不抛」「不可逆」「只增不减」，实现漏一个分支 | `appendLedger` 的 `ensureLayout` 在 `try` 外；`promote` 的密钥扫描被 `[]` 短路；`drain` 第 3 次失败直接删 |
| **白名单只防一个方向** | 校验写了，但只覆盖顶层 / 只覆盖一种输入形态 | 项目层 `unknownKeys` 只查顶层；`normalizeId` 的 `lossy` 只判长度/截断/非 ASCII |
| **双实现漂移** | 同一个裁决有两份实现，其中一份落后 | `memory_resolve` vs `mutations.accept`（merge 提案一份合并、一份静默删除） |
| **静默失败** | 返回 `ok: true` 但什么都没发生 | 配置页 33 个字段保存后丢弃；`guards` 的 revision 在 RPC 面不可达 |

**计数：P0 × 5 · P1 × 25 · P2 × 48**（另有 20 条「待确认」，需要真实宿主才能定级）。

### 必须先修的 5 条

1. **`normalizeId` 碰撞 → 后写的记忆静默覆盖先写的**（数据丢失，无报错无提案）
2. **推广包的密钥硬排除在默认配置下完全失效**（密钥进可分享产物）
3. **配置页 33 个用户偏好字段可编辑但保存静默丢弃**（改配置不生效，值回弹，零提示）
4. **「行配置」页保存写进仓库级 `config.json`**（层级错位 + 污染 git + 影响团队）
5. **`ask()` 的 rejected promise 变成 unhandledRejection**（Node 22 默认终止宿主进程）

## 2. P0 —— 必须在下一个版本前修

### P0-1 `normalizeId` 碰撞导致静默覆盖：不同标题归一化成同一个 id

- **位置**：`lib/model.js:129-144`（`lossy` 守卫）、`lib/store.js:278`（`writeEntry` 无存在性保护）
- **触发条件**：两条标题只差**分隔符**（`-` / `_` / 空格）或**大小写**。`normalizeId` 把 `[\s-]+` 统一成 `_`、再 `replace(/_+/g,'_')`，这三步都会丢信息，但 `lossy` 只判「长度 < 4 / 发生截断 / 含非 ASCII」。
- **实证**（`.tmp-audit/lead-probe-a.mjs`）：

  ```
  "deploy-staging connection pool cap"  → deploy_staging_connection_pool_cap
  "deploy_staging connection pool cap"  → deploy_staging_connection_pool_cap
  落盘条数 = 1（期望 2）→ 标题 = deploy_staging connection pool cap
  ❌ 后写静默覆盖先写
  ```

- **影响**：第一条的正文、回执、`supersedes` 链一起消失，`memory_remember` 返回「已记住」。这是 `docs/05 §7.6` 那类 bug **没修完的一半**（当时只补了「中文被整体丢掉」）。
- **修复**：`lossy` 增加「归一化前后长度不等」或「原文分隔符多于归一化后的 `_`」判定；**并且**在 `writeEntry` 里加存在性检查 —— G2 判据 2「id 在语料里唯一」（`docs/03:195`）目前**没有任何消费者**。两道闸都要有。

### P0-2 推广包的「含密钥硬排除」在默认配置下完全失效

- **位置**：`lib/promote.js:127`（`const forbidden = config.safety?.forbidden ?? DEFAULT_FORBIDDEN`）、`lib/promote.js:96-98`（`haystack` 只拼 title/about/body）
- **触发条件**：默认配置。`lib/config/defaults.js:72` 的 `safety: { forbidden: [] }` 是**空数组而不是 `undefined`**，所以 `??` 永不短路。
- **实证**（`.tmp-audit/c-promote.mjs`）：

  ```
  [1] 默认配置（safety.forbidden=[]）含密钥条目 → promoted = 1   excluded = []
      条目正文是否原样进包 = true
  [1b] 显式传入 DEFAULT_FORBIDDEN → promoted = 0  excluded = [{"id":"leak","reason":"secret",...}]
  ```

- **影响**：`memory_promote` 的 schema 描述写「硬排除（终态 / 含密钥 / 无证据 / 置信不足）**永远不出现在包里**」，`write: true` 还会把它写成 `export/promotion-*.md`（一个**明确用来分享**的产物）。而 `lib/gate.js:793` 的 G3 是正确写法（`[...DEFAULT_FORBIDDEN, ...extra]`）—— 只有 promote 这一条路把扫描关掉了。
- **第二条路径**：`containsSecret` 不扫 `evidence[].excerpt`，而 `gateSafety`（`lib/gate.js:350-352`）**扫**。摘录是自由文本，把密钥贴进摘录就绕过了 promote 的整道门。
- **修复**：改成 `[...DEFAULT_FORBIDDEN, ...(Array.isArray(config.safety?.forbidden) ? config.safety.forbidden : [])]`（与 G3 同形）；`haystack` 补 `evidence[].excerpt`。补一条断言：**promote 的规则表必须是 G3 规则表的超集**。

### P0-3 配置页 33 个「用户偏好」字段保存后静默丢弃

- **位置**：`lib/config/index.js:98`（`writable: source !== 'env' && source !== 'row'` —— `default` 层被判成「可写」）、`lib/config/project.js:128-150`（`writeProjectConfig` 只保留 `PROJECT_KEYS`）
- **触发条件**：在「设置 → 插件 → 记忆库 → 配置」改任意**非** `capture/quota/template/safety` 的字段（`autonomy` / `thresholds.*` / `recall.*` / `promote.*` / `embedding.*` / `conflict.*` / `root` —— 共 33 个叶子字段），点保存。
- **实证**（`.tmp-audit/probe3.mjs` 第 1 段，走面板服务同一个 `createMutations`）：

  ```

  value.written = {}
  保存前 autonomy = balanced → 保存后 autonomy = balanced （期望 manual）
  磁盘文件 = { "schema": "dsh-memory.config/v1", "version": 1 }
  ```

  而 `describeConfig` 给这些字段的 `writable` 是 `true`，所以界面**不会**置灰。
- **影响**：用户改自主度 / 审核阈值 / 召回预算 / 推广 / 语义通道 / 根目录**全部无效**，RPC 返回 `ok: true`，界面刷新后值悄悄回弹。这正是 0.2.0 声称修掉的「作用域不可见」，只是换到了 UI 层。与 `README.md:173`、`docs/07-配置面UI设计.md:682`（「非 `project` 时输入框 `disabled`」）**相反**。
- **修复**（二选一，别两头都改）：
  - **A（最小，与文档一致）**：`writable` 改成 `source === 'project'`，tooltip 说明「默认值请在插件行配置里改」。补断言：`writable === true` 的字段集合 ⊆ `projectScoped`。
  - **B（若坚持 default 层可编辑）**：新增 `memoryBank/setRowConfig` 写 profile 层，`save()` 按 `field.source` 分流。

### P0-4 「行配置」页（部署配置层）保存落到**项目层**

- **位置**：`shared/endpoints.js:58-77`（写端点只有「写项目层」）、`client/views/config.js:1033-1037` + `client/index.js:215-224`（`plugins.row.config` 与 `plugins.item` 复用同一个 `ConfigForm` → 同一个 `save()` → `setProjectConfig`）
- **触发条件**：在「插件的行配置页」（语义上是**部署配置层**、profile 级）把 `capture.enabled` 改成 `false` 并保存。
- **实证**：`probe3.mjs` 证明 `setProjectConfig` 写的是 `projectConfigPath(root)`（仓库内文件）；`test/config.test.mjs:347-350` 顺带证明保存后该字段的 `source` 变成 `'project'`。
- **影响**：用户以为改的是本机 profile（只影响自己），实际写进了**进 git 的团队文件**，来源徽标当场从「部署配置（红）」翻成「项目配置（蓝）」。四层里「行 config」这**一层没有任何 UI 能写**。
- **修复**：给「行配置页」单独一个写入口（写 profile 的 `cordis.patch.yml` 行 config，或走宿主的 plugin-row 配置 API）；`plugins.item` 的卡片只写项目层。补断言：**两个页面调用的写端点必须不同**。

### P0-5 `ask()` 的 rejected promise 变成 unhandledRejection → 终止宿主进程

- **位置**：`lib/hooks.js:463-467`

  ```js
  try {
    ask?.(question) ?? log(`defer streak reached ${streak} — ...`)
  } catch (error) { ... }
  ```

  `try/catch` 只接同步异常。宿主真实的 `userQuestions.ask` 会返回 Promise（等用户回答），**用户取消时就是 rejected**。
- **触发条件**：`autonomy === 'balanced'` 且同一会话连续 3 次 DEFER（`lib/hooks.js:448`），且宿主提供了 `userQuestions` 服务。
- **实证**（`.tmp-audit/lead-probe-ask.mjs`）：

  ```
  ❌ 观测到 unhandledRejection： user dismissed
  exit=7
  ```

  Node 22 默认 `--unhandled-rejections=throw` → 未捕获异常 → **进程退出**。
- **影响**：这是本域唯一能**崩整个宿主**的路径，而它挂在「后台 drain」上 —— 用户不会把崩溃和「记忆库连续判不了」联系起来。
- **修复**：`const result = ask?.(question); if (result && typeof result.then === 'function') result.catch((e) => log(...)); else if (result == null) log(...)`。**`??` 不能用来兜 promise。**

## 7. 值得肯定的地方
