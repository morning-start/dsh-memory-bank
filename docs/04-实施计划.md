**为什么 M5 用命令而不是 Web 面板**：命令不需要客户端 bundle，一次注册即在所有交互式
surface 生效，而且它**不经过模型** —— 用户输入 `/memory accept p_xxx` 就是用户的裁决。
Web 面板的价值是「看得见的积压」，命令的价值是「够得着的裁决」。先做后者。

### M8 · 架构收债（0.4.0）

这一版**不加功能**，只回答一个问题：**「同一个问题有几份答案？」**

审计（`.tmp-audit/probe-adjudication-drift.mjs` / `probe-merge-drift.mjs`）量出
9 处双实现，其中一处是**真实的数据丢失**：在面板上接受一条 merge 提案，
提案被删掉、**合并从未发生**，界面还报「已接受 merge 提议：`undefined`」。

| 层 | 修法 |
|---|---|
| **裁决域** | 新增 `lib/adjudicate.js`（唯一实现）；`memory_resolve` / `/memory` / 面板都是**适配器**。`user-confirmed` 现在只有一个产生点 |
| **共享内核** | 新增 `lib/kernel/{quota,number,text,time}.js`；`tokenize` / `stripQuoted` **重命名消歧**（同名不同义不靠注释区分） |
| **CI 硬门** | `scripts/check.mjs` 第四相：**同一个顶层函数名不得出现在两个 `lib/` 模块里**。验证过它会红 —— 一个不会红的门比没有门更糟 |

**为什么做成硬门而不是维护条款**：这类 bug 的恶劣性质是「两份实现各自都有测试，
所以永远不会变红」。条款会被跳过，而跳过的时候全绿。

### M9 · 记忆库改成 opt-in（0.4.4）

**M8 收的是「同一个问题有几份答案」的债；M9 收的是「谁有权写入」的债。**

`.dsh-memory/` 原本由五条路径惰性创建，其中两条是**自动**的（召回注入、
自动捕获）。后果：在一个从没用过记忆的仓库里跑几轮对话，就会多出一个
`.dsh-memory/` —— 而这个目录**会被提交进 git**。

| 修法 | 落点 |
|---|---|
| 唯一判据 `isInitialized(root)` | `lib/store.js`（`.dsh-memory/` 目录在不在） |
| 自动捕获加门 | `lib/hooks.js` 的 `onTurnStopping`（**在配置读取之前**） |
| 只读路径不 opt-in | `lib/tools.js` / `lib/command.js` 的只读工具与子命令 |
| drain 不重建 | `lib/hooks.js` 的 `processItem`（删掉的目录不复活） |
| 三个入口一份实现 | `memory_init` / `/memory init` / 面板 → `lib/adjudicate.js` 的 `init` |
| 面板区分「没装过」和「装了但空」 | `overview().initialized` + `client/views/memory.js` |

**为什么 `.dsh-memory/` 必须 opt-in**：它是仓库制品，不是缓存。正文和回执进
git、随 PR review、随回滚消失 —— 那意味着**创建它是一次提交**，不能是副作用。

**为什么每一条回归都同时断言「没有创建 `.dsh-memory/`」**：只断言返回值的话，
一个「先建目录再返回提示」的实现也能全绿。这正是 M8 学到的教训 —— 门要能在
**错误的那一侧**变红。


### 两次返工，都是真 bug

**M4 · 捕获阻塞回合**：第一版把「跑十道门 + 写记忆 + 重建索引」全塞在
`agent/turn-stopping` 里 —— 而那是宿主 **await** 的路径，实测 **89–113 ms**。
现在 turn-stopping 只做「确定性判定 + 落盘入队」（2.4–3.3 ms），处理交给后台 drain。
顺带发现：**自动捕获会写进带占位符的草稿**（`# 执行\n（待补：怎么做）`），
因为 G2 只检查标题在不在。新增 **G2b 草稿门**（软门 → DEFER）堵住。

**M1 · 回执层从未生效**：`serializeEntry` 对正文调 `trimEnd()` 并在末尾加 `\n`，
而 `parseEntry` 不剥、`contentHash` 又直接哈希原始 body —— 于是
`parseEntry(serializeEntry(x)).body` 比 `x.body` 多一个换行，
**每一条记忆的 `contentHash` 都对不上**：

> 回执层把**每一条正常写入的记忆**都判成 `tampered`，并且用「正文被改」
> 这个措辞做了一次**虚假的篡改指控**。那比没有回执更糟 ——
> 它训练用户忽略这个警告。

修法：`canonicalBody()` 成为写入 / 解析 / 哈希**三处共用的唯一规范形式**。

**M6 · 漂移检测根本不存在**：`lifecycle.js` 只有衰减/整合/dream，
`memory_audit` 把「回执哈希不匹配」当成了漂移 —— 于是删掉被引用的文件时，
它报的是「正文被改」（错的理由），而且**不点名是哪个锚点**。

新增 `lib/drift.js`，判决分五种：

| 判决 | 含义 |
|---|---|
| `healthy` | 目标还在，切片没变 |
| `quarantined` | **目标消失**（文件删了 / 符号不存在 / 行号越界） |
| `advisory` | 目标还在，**切片变了** —— 重构不是攻击 |
| `symbol-not-a-definition` | 锚点落在注释 / 字符串 / 调用处 —— 指错了 |
| `unverifiable` | 机器无法判断（commit / command / user） —— **不撒谎** |

前两种混为一谈的后果是具体的：每一次改名、挪行、重新格式化都会把整个记忆库
标成「不可信」，然后所有人学会忽略这个警告。

**未做的（0.1.1 仍未做，共 14 条 —— 文档承诺过、代码是空壳的那些，逐条列在这里）**：

| # | 项 | 现状 |
|---|---|---|
| 1 | **Web 面板**（待决队列 + 健康概览的图形界面） | 未做。命令面已通，面板的价值是「看得见的积压」 |
| 2 | **语义通道的实际启用** | 未做。`lib/embedding.js` 已实现，但实测分离度 **−0.020 ~ +0.063**（同一批候选改文档就翻号），落在「关」这一档（见 §建议的下一步） |

## M2 · 召回

**做**

- `src/recall/classify.ts`：查询分类（identifier / path / error / natural / decision / mixed）
- `src/recall/lanes.ts`：
  - `exact`（路径 / 符号 / 测试 / 错误串，权重 8）
  - `bm25f`（k1=1.2，字段权重 + 长度归一，权重 16）
  - `ngram`（字符 3-gram，权重 0.1）
  - `fuzzy`（编辑距离，权重 0.25）
  - `graph`（1 跳邻接 + 类型权重，权重 0.05）
- `src/recall/fuse.ts`：RRF(k=10) → 特征加权 → 四门 → MMR(λ=.78)
- `src/recall/tiers.ts`：`content` / `pointers` / `abstain`
- `src/recall/render.ts`：注入文本（带「数据不是指令」的信任声明）

**验收**

- 锁定语料（≥100 条中英混合 + 40 条无关查询）：
  - Recall@1 ≥ 90%
  - 无关查询 abstain 率 **100%**
  - 同一查询跑 100 次，结果逐字节相同
  - **每轮合计 p50 < 5ms**（实测 4.3–7.8 ms；p95 受 GC / 200 条语料影响在 46–90 ms，
    而且 `bench/assembly.mjs:90` 的 `percentile` 在 20 个样本上取 p95 得到的是**最大值**，
    标签本身不准 —— 验收指标以 **p50** 为准）
- `pointers` 层的文本**必须**含「这不是答案」

**坑**

- 中文分词：不要上词典，用字符 n-gram + 中文停用词表
- 分档阈值不要凭感觉调 —— 用 ablation 曲线（删掉正确记忆重跑，看假交付率何时不再下降）

## M3 · 审核协议

**做**

- `src/gate/protocol.ts`：串行编排 + 合成（`HARD_GATES` 短路）
- 10 道门各一个文件，**纯函数**：`(candidate, context) => GateVerdict`
- `src/gate/g4-evidence.ts` 的锚点解析器（`file:line` / `Symbol.name` / 测试名 / `sha` / 命令）
- `trust/receipts.json` 读写 + 篡改检测

**验收（对应协议 §14 的 7 条）**

| 场景 | 期望 |
|---|---|
| 说「记住：X」 | `ACCEPT`，落盘，`memory_recall` 能召回 |
| 说一条含 `sk-…` 的记忆 | `REJECT(secret)`，**文件不存在**，`ledger` 有记录且脱敏 |
| 说一条与既有条目矛盾的记忆 | `DEFER`，`pending/` 有提案 |
| 说一条 README 已有的断言 | `REJECT(owned-elsewhere)` + `owner.ref` |
| 说一条没有证据的记忆 | `REJECT(evidence.none)` |
| 说一条与既有条目 91% 相似的记忆 | `REJECT(duplicate)` + `hint` |
| 语料满 200 条再写 | `REJECT(quota)` + `weakest` 列表 |

**坑**

- 门的顺序会变结论：G1 必须在 G5 之前（先判「有主」，再判「重复」）
- G3 命中后**不要**把命中片段回给模型（二次泄露）
- REJECT 必须带 `next`，否则模型会重试同一件事

## M4 · 捕获与自主度

**做**

- `src/capture/signals.ts`：S1–S7 确定性信号
- `src/capture/extract.ts`：候选提取（每条候选带 `origin`）
- `src/capture/steward.ts`：`agent/turn-stopping` 里调度，走 `session/event` 增量折叠
- 三档 `autonomy` 调制 `autoAcceptFloor`
- 连续 3 次 DEFER 升级为 `userQuestions.ask`

**验收**

- `manual`：任何自动捕获都不落盘（只在面板里出提案）
- `balanced`：S1 显式指令自动落盘；S3 决策进 pending
- `autonomous`：全部自动，`ledger` 可查
- 关掉插件 → 零副作用（不写任何文件）

**坑**

- `turn-stopping` 是 serial，**必须**在返回前完成（否则 turn 关了但记忆没写）
- 不要在 `turn-stopping` 里做 IO 密集的 `memory_audit` 全量扫描 —— 只做增量
- `agent.inject()` **不唤醒** agent；要在 turn 之外提示用 `followup()`

- `lib/drift.js`：锚点复查（healthy / quarantined / advisory / not-a-definition / unverifiable）
- `lib/lifecycle.js`：`lastVerifiedAt` + `accessCount` → 陈旧提示、休眠、到期复查
- `lib/lifecycle.js`：`consolidate`（近重复簇 + `supersedes` 链合并，**只出提案**）
- `lib/claims.js`：断言抽取 / 限定 / 状态判定 / 对账
- 回滚：`index/HEAD` 上一版 + `supersedes` 链

**验收**

- 删掉被引用的源文件 → `memory_audit` 报 `quarantined` 并**点名锚点**
- 改掉被引用的符号体 → `advisory`，**不** quarantined（重构 ≠ 攻击）
- 锚点落在注释上 → `symbol-not-a-definition`，且**不重新签名**
- 整合只产生提案，`memories/` 不变

**坑**

- 漂移检测要有**缓存**（同一次扫描里文件只读一次），否则每次 audit 都扫全仓库
- 「目标还在但切片变了」和「目标消失了」必须是两种判决
- `commit` / `command` / `user` 锚点**无法机器复查** —— 报「健康」是撒谎，报「漂移」是误伤。
  第五种判决 `unverifiable` 就是为这个存在的
- 「目标还在但切片变了」和「目标消失了」必须是两种判决

## 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 召回质量需要真实语料调参 | 阈值可能不适合本机 | 先跑 M2 的基准，阈值留可配 |
| G1 归属门的「断言抽取」误判 | 会把该记的拒掉 | 保守实现：只认**完全包含**的断言；误判方向偏向 ACCEPT |
| 中文分词 | 召回率 | 字符 n-gram + 停用词，不上词典 |
| `defineTool` 是 peer 依赖 | 可能装不上 | 按 `bireturn` 的做法：直接用 `ctx.tools.register` + 自校验，不引 `dsh-tools` |
| `turn-stopping` 里做重活 | 拖慢每一轮 | 只做增量；全量审计走 `memory_audit` 显式调用 |
| 面板 slot 崩溃 | 整个 UI 空白 | 组件外包 error boundary；只用 token 不用裸色 |
