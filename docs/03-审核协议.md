# 记忆审核协议（Memory Review Protocol, MRP）v1

> 本文件是**规范**不是说明。实现与本文冲突时以本文为准；改本文是协议变更。
> 相关：[设计](./02-设计.md) · [参考分析](./01-参考分析.md)

---

## 0. 这个协议解决什么

一条记忆一旦写入，它的成本由**未来每一个会话**支付；而拒绝它的成本只由**这一次**支付。
所以协议的全部设计目标是一句话：

> **让「不记」成为默认结果，让「记」必须赢得它。**

协议是**确定性**的：同样的候选 + 同样的仓库 + 同样的配置 → 同样的裁决。
协议**不调用模型**。（唯一例外是 G6 的 `semantic-conflict` 探针，且默认关闭。）

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| **候选 (Candidate)** | 一份尚未落盘的记忆提案：`body` + `evidence[]` + `about` + `kind` + `provenance` |
| **门 (Gate)** | 一个纯函数 `Candidate × Context → Verdict` |
| **裁决 (Verdict)** | `pass` \| `downgrade(reason)` \| `refuse(code, detail)` |
| **结论 (Decision)** | 十道门合成的三值：`ACCEPT` \| `REJECT` \| `DEFER` |
| **回执 (Receipt)** | 与正文分离的信任记录，绑内容哈希 + 证据根 + 校验者 |
| **提案 (Proposal)** | `DEFER` 的产物，进 `pending/`，等用户裁决 |

---

## 2. 协议总览

```
Candidate
   │
   ├─ G1 归属 ──────────── refuse(owned-elsewhere) ──► REJECT
   ├─ G2 形态 ──────────── refuse(shape) ───────────► REJECT
   ├─ G2b 草稿 ─────────── refuse(shape.draft) ─────► DEFER    ← 软门，不短路
   ├─ G3 安全 ──────────── refuse(secret) ──────────► REJECT   ← 不可绕过
   ├─ G4 证据 ──────────── refuse(evidence) ────────► REJECT
   ├─ G5 重复 ──────────── refuse(duplicate) ───────► REJECT
   ├─ G6 冲突 ──────────── refuse(conflict) ────────► DEFER
   ├─ G7 配额 ──────────── refuse(quota) ───────────► REJECT
   └─ G8 置信 ──────────── refuse(confidence) ──────► DEFER
                                                       │
                                              全部 pass ┴──► ACCEPT
```

**门是串行的，但每道门都会跑完并留下意见**（用于提案展示与审计）。
第一道 `REJECT` 决定性拒绝后短路；`DEFER` 不短路（收集全部 DEFER 理由）。

### 2.1 合成规则

```ts
function decide(verdicts: GateVerdict[]): Decision {
  const hard = verdicts.find(v => v.kind === 'refuse' && HARD_GATES.has(v.gate))
  if (hard) return { kind: 'REJECT', code: hard.code, detail: hard.detail, all: verdicts }

  const soft = verdicts.find(v => v.kind === 'refuse')
  if (soft) return { kind: 'DEFER', code: soft.code, detail: soft.detail, all: verdicts }

  return { kind: 'ACCEPT', all: verdicts }
}

const HARD_GATES = new Set(['G1', 'G2', 'G3', 'G4', 'G5', 'G7'])
```

| 门 | refuse 时 | 为什么 |
|---|---|---|
| G1 归属 | **REJECT** | 「已经有主」是确定的，不需要人裁 |
| G2 形态 | **REJECT** | 可修，回给模型改 |
| G2b 草稿 | **DEFER** | 草稿值得记，只是还写不好 |
| G3 安全 | **REJECT** | 不可绕过，也不该拿给用户看 |
| G4 证据 | **REJECT** | 可修：补锚点 |
| G5 重复 | **REJECT** | 确定重复，回给模型用 `replace` |
| G6 冲突 | **DEFER** | 「谁对」是人的判断 |
| G7 配额 | **REJECT** | 确定超限，列出最弱候选让模型/人决定退休谁 |
| G8 置信 | **DEFER** | 「值不值得记」是人的判断 |

> **G2b / G6 / G8 是 DEFER 的三个来源。** 这是刻意的：只有「只写了个草稿」、
> 「两条都成立但相互矛盾」和「说不清值不值得」这三件事需要人。
> 其余都是可机械判定、可回给模型修的。

## 3. 输入契约

### 3.1 `Candidate`

```ts
interface Candidate {
  id: string                      // ^[a-z0-9]+(_[a-z0-9]+)*$
  title: string                   // 1..120 字，一行
  kind: 'decision' | 'pitfall' | 'convention' | 'correction' | 'fact' | 'capability'
  about: string                   // 「这条记忆是干什么用的」，进索引
  body: string                    // Markdown 正文，必须含 G2 要求的要素
  evidence: Evidence[]           // 至少 1 条
  scope: string[]                 // 适用面，如 ["repo:acme/api"]
  triggers?: string[]             // 什么查询应唤起它
  supersedes?: string[]           // 本条目取代的 id
  provenance: 'user-asserted' | 'measured' | 'file-derived' | 'self-concluded'
  confidence?: number             // 0..1，缺省由 G8 计算
  origin: {
    sessionId: string
    turn: number
    messageSeq?: number
    signal?: string               // 命中的捕获信号，如 'S1'
  }
}

interface Evidence {
  kind: 'file' | 'symbol' | 'test' | 'commit' | 'command' | 'doc' | 'user'
  ref: string                     // repo-relative path / Symbol.name / 测试 id / sha / 命令 / 用户原话引用
  excerpt?: string                // 可选摘录
  hash?: string                   // 由 G4 计算并写入回执
}
```

**硬约束**：`id` / `title` / `kind` / `about` / `body` / `evidence` / `provenance` / `origin` 必填。
缺任何一个 → G2 `refuse(shape)`，**且不进入后续门**。

### 3.2 `Context`

```ts
interface Context {
  workspaceRoot: string
  memoryRoot: string              // <workspace>/.dsh-memory
  // 没有 globalRoot —— 本插件不做全局存储
  config: ResolvedConfig
  corpus: MemoryEntry[]           // 当前活跃语料（已过 lifecycle 过滤）
  treeHash: string                // 工作树指纹，用于缓存
  now: string                     // ISO-8601
}
```

**确定性要求**：`Context` 里不许有 `Date.now()` 之外的时序输入，且 `now` 由调用方注入。

## 4. 门规范

### G1 · 归属门（Ownership）

**问的**：这条断言是不是已经由某个更适合的载体拥有？

**判据**（按顺序，命中即 `refuse(owned-elsewhere)`）：

| # | 检查 | 例子 |
|---|---|---|
| 1 | `AGENTS.md` / `CLAUDE.md` / `.cursorrules` 等**规则文件**已含该断言的规范句 | 「提交前跑 lint」→ 规则文件已有 |
| 2 | 仓库**权威文档**（`README`、`docs/**`）已由同一断言拥有 | 「怎么启动 dev server」→ README 有 |
| 3 | **回归测试**已编码该断言 | 「`parse()` 对空串返回 `null`」→ 有单测 |
| 4 | **代码本身**是该断言的载体（类型、断言、常量） | 「默认端口是 8080」→ 常量里写着 |
| 5 | 已有**更具体的记忆条目**（同 `id` 前缀或 `supersedes` 链）拥有 | — |

**实现**：
- 1/2 用「断言三元组」抽取 + 语法化匹配（主语/谓语/宾语 + 同义归并），不调模型
- 3 用测试索引（`test/**` 里的 `it(`/`test(` 描述）
- 4 用符号索引

**输出**：
```jsonc
{ "gate": "G1", "kind": "refuse", "code": "owned-elsewhere",
  "detail": { "owner": { "kind": "doc", "ref": "README.md:42" }, "why": "该断言已由文档拥有" } }
```

> 这条门是「知道自己什么时候**不该**记」的正面实现。它是**硬拒**：
> 一条已经有人拥有的断言再进记忆，唯一的效果是未来某天两份副本开始漂移。

---

### G2 · 形态门（Shape）

**问的**：一条记忆只讲一件事吗？必需要素齐全吗？

**判据**：

| # | 检查 | 拒绝码 |
|---|---|---|
| 1 | 必填字段齐全且类型正确 | `shape.missing=<field>` |
| 2 | `id` 匹配 `^[a-z0-9]+(_[a-z0-9]+)*$`，且在活跃语料里唯一 | `shape.id` |
| 3 | `title` ≤ 120 字且不含换行 | `shape.title` |
| 4 | `body` 含**六要素**（可配置模板，默认见下） | `shape.template` |
| 5 | `body` 长度 ∈ [80, 8000] 字 | `shape.length` |
| 6 | 单主题：`body` 的标题数 ≤ 3 且无 `## 以上都不是` 之类的多主题标记 | `shape.multi-topic` |

**默认六要素**（沿用本机既有写入门禁的口径，见 `.dsh-memory/data/policy.json`）：

```markdown
# 功能名
<一句话：这条记忆讲什么>

# 生效条件
<什么情况下适用>

# 子功能
<涉及的组件/文件/命令>

# 执行
<怎么做>

# 验证方式
<怎么确认它还是对的 —— 必须是可执行的>

# 不适用条件
<什么时候它不管用 —— 防止被过度泛化>
```

要求「不适用条件」是刻意的：**一条没有边界的记忆会污染所有它看起来相关的判断。**

**输出**：`refuse(shape)` + 缺失项清单（模型据此重写，**不是**重试无用）。

---

### G2b · 草稿门（Drafting）

**问的**：六要素真的**填实**了吗，还是只留了占位符？

**标记**：`（待补：<这一段该写什么>）`。

**判据**：正文含任一占位符 → `refuse(shape.draft)` + 缺失段清单。

**软门。** 草稿值得记，只是还写不好 —— 所以是 `DEFER`，不是 `REJECT`。

**为什么必须有这道门**：自动捕获只产出草稿。它从这一轮的真实内容里能填的就填 ——
用户那句话 → 生效条件，助手最后那段话 → 执行，编辑过的文件 → 子功能，
跑过的命令 → 验证方式。**填不了的必须留占位符。**

没有这道门时，一条 `# 执行\n（待补：怎么做）` 的草稿会通过 G2（标题都在）、
通过 G8（锚点确实出现在正文里），然后**被当成一条真记忆写进去**。

> 那是这个系统能犯的最严重的错：**它把「我不知道」写成了一句看起来像事实的话。**

**软门不短路**：G3–G8 仍然跑完，提案里带上完整意见 —— 你在裁决时看得到
「它连哪一段没想清楚」。

**填实的两条路**：

| 路 | 谁填 | 代价 |
|---|---|---|
| `capture.draft: template`（默认） | 确定性模板，填不满就留占位符 | 零 |
| `capture.draft: subagent` | **后台 drain 里**跑一次子 Agent | 一次模型往返（钱和时间） |

子 Agent 也**不能**跳过门：它只填一部分时，缺的段仍然补占位符、仍然 `DEFER`。

**为什么子 Agent 只能在 drain 里跑**：`agent/turn-stopping` 是宿主 **await** 的路径。
在它里面 spawn 一个子 Agent 等于让用户多等一次完整的模型往返（秒级）——
比同步重建索引（~92 ms）还糟。

### G3 · 安全门（Safety）

**问的**：正文或证据里有没有不该进仓库的东西？

**判据**：对 `body + evidence.excerpt + title` 跑**高精度正则表**，命中即 `refuse(secret)`。

默认规则（`config.safety.forbidden`，可覆盖，**只增不减**）：

```jsonc
{
  "forbidden": [
    "-----BEGIN [A-Z ]*PRIVATE KEY-----",
    "\\bsk-[A-Za-z0-9_\\-]{20,}",
    "\\bAKIA[0-9A-Z]{16}\\b",
    "\\bgh[pousr]_[A-Za-z0-9]{20,}\\b",
    "(?i)\\bapi[_-]?key\\s*[:=]\\s*[A-Za-z0-9_\\-]{16,}",
    "(?i)\\b(app[_-]?secret|appsecret|client[_-]?secret|secret[_-]?key|access[_-]?key)\\s*[:=]?\\s*[A-Za-z0-9]{16,}",
    "(?i)\\b(password|passwd|pwd|密码|口令)\\s*[:=：]\\s*\\S{6,}",
    "(?i)\\bBearer\\s+[A-Za-z0-9._\\-]{20,}",
    "[a-z][a-z0-9+.\\-]*://[^/\\s:@]+:[^/\\s@]+@"
  ]
}
```

**纪律**：

1. **宁可漏报也不误伤正常记忆** —— 长 hex（git SHA）等易误伤模式**刻意不收**。
2. 命中后**不落盘**，也**不把命中内容回显**给模型（只回 `code` 与命中的规则序号）。
3. 拒绝后**记入 `ledger.jsonl` 的负记忆**，但正文脱敏（按命中片段替换为 `***`）。

> 为什么是硬拒而不是 DEFER：把一条含密钥的记忆拿给用户裁决，本身就是二次泄露。

### G3b · 注入门（Injection）

**问的**：这条记忆是不是在**指挥宿主**？

**判据**（抄 OwnMem `lib/memory-lifecycle.mjs:48-68`，**故意窄**）：

```ts
// 三段必须相邻：动词 + 被寻址的层 + 它命名的产物
const INSTRUCTION_OVERRIDE =
  /\b(?:ignore|override|bypass|disregard)\b.{0,24}?\b(?:system|developer|user)\b[\s-]{0,3}(?:instructions?|prompts?|messages?)\b|(?:忽略|无视|绕过|覆盖).{0,6}?(?:系统|开发者|用户).{0,4}?(?:指令|提示词|消息)/iu
```

**为什么这么窄**（这段理由要照抄进实现注释）：

> 上一版接受 `system|developer|instruction|policy|safety` 中任意一个，中文分支接受「规则」「安全」——
> 两者都是工程散文的日常词汇。实测在 356 条语料上**永久屏蔽了 4 条记忆，一次真攻击也没抓到**：
> 包括描述这条防御本身的记忆、一条说 JSON 解码器忽略未知键的笔记、两次普通的「覆盖」用法。
>
> 所以现在两半都要求三段相邻。**精确性是靠匹配器买来的，不是靠软化后果** ——
> 与证据漂移不同，一条指挥宿主的记忆是可能的投毒，爆炸半径是**提权**而不是过时建议，
> 所以它保持硬阻断。

**同一个匹配器必须同时读正文与查询**（`memoryTextOverridesInstructions`）：
正文从来不是覆盖的唯一入口；直接敲进查询的注入，不能因为换了面就被当成普通自然语言。

**输出**：`refuse(injection)` —— 硬拒，且**不回显命中片段**。

### G3c · 行动风险（Action Risk）

不是门，是**回执上的一栏**，影响交付而不影响写入：

```ts
actionRisk(text) =
  R5 if 破坏性动作 ∧ 安全域     // 「删除凭据」「强删密钥」
  R4 if 破坏性动作 ∨ 外部动作    // 「发布」「部署」「清空」
  R3 if 安全域                  // 「密钥」「权限」「鉴权」
  R2 if kind ∈ {preference, correction}
  R1 否则
```

词表中英双语，抄 `memory-lifecycle.mjs:44-46`：

```ts
DESTRUCTIVE = /\b(?:drop|delete|erase|purge|destroy|force[- ]?remove)\b|删除|清空|销毁|强删/iu
EXTERNAL    = /\b(?:publish|deploy|push|release|send|upload|charge|bill|purchase)\b|发布|部署|推送|发送|上传|付费|购买|扣费|上线/iu
SECURITY    = /\b(?:credential|secret|token|password|permission|entitlement|auth(?:entication|orization)?)\b|凭据|密钥|密码|权限|鉴权|授权/iu
```

**纪律**：风险来自**变更面**，不来自自述。记忆不能在自己的正文里声明一个更低的等级。
`R4/R5` 的记忆召回时**必须**带「这条建议涉及不可逆操作」的标注。

### G4 · 证据门（Evidence）

**问的**：每条断言都有可解析的锚点吗？锚点现在还对得上吗？

**判据**：

| # | 检查 | 拒绝码 |
|---|---|---|
| 1 | `evidence.length ≥ 1` | `evidence.none` |
| 2 | 每条 `evidence.ref` 能解析 | `evidence.unresolved:<ref>` |
| 3 | 解析出的内容哈希 == `evidence.hash`（首写时计算并绑定） | `evidence.drifted:<ref>` |
| 4 | 若 `kind === 'symbol'`，锚点必须落在**定义**上 | `symbol-not-a-definition` |
| 5 | `body` 里出现的路径 / 符号，必须在 `evidence` 里至少出现一次 | `evidence.uncovered:<token>` |

**第 3 条的语义**（抄 OwnMem `TECHNICAL.md:33-39`）：
哈希对得上只证明「内容与回执一致」，**不证明断言正确**。
所以 G4 判的是「证据还在不在原位」，不是「证据支不支持这个结论」。

**第 4 条为什么重要**：
锚点可以**稳定但错位** —— 一条教训说「这个符号不该存在」，却锚在说这句话的注释上。
指纹稳定、回执健康，但它在给错的代码块背书。**这种形态必须报出来，不能重新签名**
（重新签只是又签了一遍注释）。

**首写 vs 复查**：

| 阶段 | 行为 |
|---|---|
| 首写（无 `hash`） | 解析锚点 → 计算 `hash` 写入回执；解析失败则 `refuse` |
| 复查（有 `hash`） | 解析 → 比对：一致 `pass`；不一致 `downgrade(evidence-drift)`；目标消失 `refuse(evidence.gone)` |

### G5 · 重复门（Duplicate）

**问的**：语料里是不是已经有一条在说同一件事？

**判据**（抄 OwnMem `lib/memory-duplicates.mjs:7-13` 的**双阈值合取**）：

```ts
// 1. 指纹文本：先剥离代码块，否则同一段代码复制两遍会算成重复
const text = stripCodeBlocks(`${candidate.about}\n${candidate.body}`)

// 2. 特征：全部 token + 三元 token 组前缀 't3:' + 每 4 字符滑动的 12 字符前缀 'c12:'
const features = [...tokens(text), ...trigrams(text).map(t => `t3:${t}`),
                  ...slidingPrefixes(text, 12, 4).map(p => `c12:${p}`)]

// 3. 双指纹：SimHash 用 (1 + log2(freq)) 加权；MinHash 用 64 个置换取最小哈希
const simhash = simhashSimilarity(candidate, existing)   // 0.84
const minhash = minhashSimilarity(candidate, existing)   // 0.72

if (existing.id === candidate.id && (simhash > 0.95 || minhash > 0.95)) return pass   // 幂等重写
if (simhash >= 0.84 && minhash >= 0.72)
  return refuse('duplicate', { existing: existing.id, simhash, minhash })
```

**为什么是合取而不是取最大**：SimHash 对「整体词袋相似」敏感，
MinHash 对「集合成员重叠」敏感。只用一个，会在**短条目**上误报
（两个两句话的记忆共享全部 token 但讲的是不同的事）。
两个都过，才是「同一件事的两种写法」。

`min_features = 16` 是下限：特征数不足时**跳过检测**而不是猜
—— 一条短记忆的特征少到任何相似度都不稳定。

**输出**必须给出**怎么做**：

```jsonc
{ "gate": "G5", "kind": "refuse", "code": "duplicate",
  "detail": { "existing": "staging_timeout_pool_cap", "simhash": 0.91, "minhash": 0.83,
              "hint": "用 memory_remember 传 id=<existing> + supersedes 覆盖，或改用 memory_resolve 编辑" } }
```

**只 warning 不阻断？不。** OwnMem 的 audit 只报 `warning`，因为它的写入是人；
本插件的写入可能自动发生，所以重复是**硬拒**。用户可以裁决「接受」，
但那时是用户签字，不是协议放行。

---

### G6 · 冲突门（Conflict）

**问的**：这条候选是不是和既有条目**矛盾**？

**判据**（两级，第二级默认关闭）：

| 级 | 方法 | 默认 |
|---|---|---|
| 6a | 已有 `contradicts` 边指向该 id | **开** |
| 6b | 同 `kind` + 同 `about` + 否定词翻转（「必须」↔「不要」） | **开** |
| 6c | 语义蕴含矛盾（需模型/向量） | **关** |

**为什么是 DEFER 不是 REJECT**：
「A 说 X，B 说非 X」→ 协议不知道谁对。这不是「记忆不该存在」，是「需要人收口」。
所以进 pending，**两条都保留**，`supersedes` 由人点。

**输出**：
```jsonc
{ "gate": "G6", "kind": "refuse", "code": "conflict",
  "detail": { "with": "retry_policy_4xx_set", "axis": "negation-flip",
              "left": "4xx 要重试", "right": "4xx 不要重试" } }
```

### G7 · 配额门（Quota）

**问的**：这个 scope 到顶了吗？

**判据**：配额是**棘轮**，不是配置（抄 OwnMem `lib/memory-audit.mjs:118-156`）。

```jsonc
// .dsh-memory/quota.lock.json
{
  "schema": "dsh-memory.quota/v1",
  "mode": "growth",            // growth → ratchet，一次性，不可逆
  "growth_threshold": 50,      // 活跃条目达到这个数就切换
  "max_active": null,          // ratchet 时锁成当时的条目数
  "transitioned_at": null
}
```

| 状态 | 行为 |
|---|---|
| `growth` 且 `activeCount < 50` | 放行 |
| `growth` 且 `activeCount >= 50` | **切换**到 `ratchet`：`max_active = activeCount`，写回并报 `info quota-transition` |
| `ratchet` 且 `activeCount < max_active` | 放行 |
| `ratchet` 且 `activeCount >= max_active` | `refuse(quota)` |
| `--write-lock` 尝试抬高 `max_active` | **拒**：`quota-ratchet-raise`（只降不升） |

**为什么是棘轮而不是配置**：

> 一个每次绑定就被手工抬高的字节预算不是配额。
> OwnMem 的这个字节上限**七周被手工抬高六次**，然后被删掉了。

到顶时 `refuse(quota)`，**并列出最弱候选**（按 §10 的 `weakness` 排序，最多 5 条）：

```jsonc
{ "gate": "G7", "kind": "refuse", "code": "quota",
  "detail": { "scope": "repo:acme/api", "used": 200, "limit": 200,
              "weakest": ["old_ci_note", "temp_workaround_2026_03"],
              "hint": "先 memory_forget 退休其中一条，或把它们合并成一条" } }
```

**提名的纪律**（抄 `memory-swap-nomination.mjs:134-181`）：

- 入链 ≥2 的 **hub 直接排除** —— 它被别的条目依赖，删它会连带断链
- 排序：`never-delivered` 优先 → 未交付天数降序 → 证据数升序 → 字节降序
- **无遥测时必须说**：`no retained telemetry — delivery is unknown, not zero`
  —— 不许把「未交付」读成「从未使用」

> **audit 拒绝写入，但它不挑受害者。** 只列最弱候选，不自动退休。

### G8 · 置信门（Confidence）

**问的**：这条候选的综合置信过线了吗？

**计算**（加权和，全部可解释、**全部与语料规模无关**）：

```ts
confidence =
    0.30 * signalStrength(candidate.origin.signal)   // S1/S2=1.0, S3-S6=0.6, S7=0.7
  + 0.25 * evidenceStrength(candidate.evidence)      // 见下
  + 0.15 * provenanceWeight(candidate.provenance)    // user-asserted=1, measured=.9,
                                                     // file-derived=.8, self-concluded=.5
  + 0.20 * anchorCoverage(candidate)                 // 正文有没有提到它引用的东西
  + 0.10 * scopeClarity(candidate.scope)             // 有明确 scope=1，空=0.3
```

`evidenceStrength`（抄 OwnMem `memory-compiler.mjs:705-711` 的相对序）：

```ts
{ user: 1.0, test: 0.9, symbol: 0.8, file: 0.8, commit: 0.7, command: 0.6, doc: 0.5 }
```

`anchorCoverage` = **正文/摘要里出现过的证据锚点占比**。一条引用 `src/db/pool.ts`
却整篇没提这个文件的记忆，是在**给错的代码块背书** —— 这是它唯一的错，也是它必须掉分的原因。

> **为什么 coverage 不能算「与既有语料的相似度」**（v0.1.0 的实现，已被本版替换）：
>
> 那样一来，语料为空时回退 0.5、非空时按相似度打分，结果是**第二条同类型记忆
> 比第一条更难落盘**。那等于惩罚「积累」，而积累是这个系统唯一的目的。
>
> 更糟的是它不单调：同一个候选在不同大小的语料上得到不同裁决，
> 而「同样的候选 + 同样的仓库 → 同样的裁决」是协议敢自动跑的前提。
>
> 权重按「一条形态完备但来源不明的记忆刚好过 0.6 地板」反解：
> `0.30·0.7 + 0.25·0.8 + 0.15·0.5 + 0.20·1 + 0.10·1 = 0.785`；
> 正文没提到锚点时掉到 **0.585**，正好低于地板。

**判据**：

| 条件 | 结论 |
|---|---|
| `confidence ≥ autoAcceptFloor`（默认 **0.60**） | `pass` |
| `confidence < autoAcceptFloor` 但 `≥ deferFloor`（默认 0.35） | `refuse(confidence)` → **DEFER** |
| `confidence < deferFloor` | 直接丢弃，**不建提案**（噪音，不打扰用户） |

**`autoAcceptFloor` 受 `autonomy` 调制**：

| autonomy | autoAcceptFloor |
|---|---|
| `manual` | 1.01（永不自动，全走确认） |
| `balanced` | 0.60 |
| `autonomous` | 0.45 |

## 5. 结论与副作用

### 5.1 `ACCEPT`

1. 计算并写入 `trust/receipts.json`（`contentHash` / `evidenceRoot` / `verifier` / `predecessor`）
2. 原子写 `memories/<id>.md`（`tmp` → `rename`）
3. 重建索引快照（内容寻址），`HEAD` 指向新快照，保留上一版
4. 追加 `ledger.jsonl`：`{ts, id, decision:"accepted", gates:[…], confidence}`
5. 若 `autonomy !== 'autonomous'` 且来自自动捕获 → 通过 `systemPrompt.context` 在下一步说一句
   「已记住：<title>」（**不打断**）

### 5.2 `REJECT`

1. **不写任何记忆文件**（`trust` 也不写）
2. (G3 命中时) 负记忆脱敏后追加 `ledger.jsonl`
3. 返回结构化结果给模型：

```jsonc
{
  "decision": "REJECT",
  "code": "owned-elsewhere",
  "gate": "G1",
  "detail": { "owner": { "kind": "doc", "ref": "README.md:42" } },
  "next": "这条断言已由 README.md:42 拥有。不要重复记录；若要修改，请改那份文档。",
  "gates": [ /* 每道门的意见 */ ]
}
```

**`next` 是必须的**：拒绝而不给下一步，模型会重试同一件事。

### 5.3 `DEFER`

1. 写 `pending/<proposalId>.json`：

```jsonc
{
  "id": "p_20261106_143012_a1b2",
  "candidate": { /* 完整 Candidate */ },
  "gates": [ /* 每道门意见 */ ],
  "deferredBy": ["G6", "G8"],
  "why": ["与 retry_policy_4xx_set 矛盾", "置信 0.41 < 0.60"],
  "createdAt": "2026-11-06T14:30:12Z",
  "expiresAt": "2026-12-06T14:30:12Z"      // 30 天未决自动过期，不写记忆
}
```

2. 追加 `ledger.jsonl`：`{ts, proposalId, decision:"deferred", gates}`
3. 返回给模型：`{ "decision": "DEFER", "proposalId": "…", "next": "已提交待决队列，用户将在面板中裁决；不要重试。" }`
4. **升级规则**：同一 scope 连续 3 次 DEFER，且 `autonomy === 'balanced'`
   → 当场 `ctx.userQuestions.ask()` 打断一次（把提案渲染成问题）。
   连续计数在 `ledger.jsonl` 上算，不用额外状态。

## 6. 用户裁决（`memory_resolve`）

```ts
memory_resolve({
  proposalId: string,
  action: 'accept' | 'reject' | 'edit',
  edit?: { title?: string; body?: string; evidence?: Evidence[]; scope?: string[] },
  reason?: string,          // 写入 ledger
})
```

| action | 行为 |
|---|---|
| `accept` | 用原候选（或 `edit` 合并后）**重跑 G1–G5, G7**；全过则落盘。**G6/G8 不再阻塞**（用户已裁） |
| `reject` | 提案移入 `pending/rejected/`，正文保留但**不参与召回**，`reason` 入 ledger |
| `edit` | 同 `accept`，但先合并 `edit` 再重跑 |

**为什么 accept 还要重跑硬门**：用户可能接受了一条现在已经含密钥、或与另一条重复的提案。
**用户的裁决权是「要不要记」，不是「跳过安全门」。**

## 7. 回执（Trust Receipt）

```ts
interface TrustReceipt {
  receiptId: string            // sha256(去掉本字段的其余全部字段)
  memoryId: string
  memorySha256: string         // 绑定的条目内容哈希
  issuedAt: string
  policyId: 'evidence-governed-v1'
  policyVersion: string

  transition: { from: LifecycleState | null; to: LifecycleState }   // 生命周期图上的边
  lifecycle: LifecycleState    // 必须 === transition.to
  actionRisk: 'R1' | 'R2' | 'R3' | 'R4' | 'R5'
  authority: 'observed' | 'advisory' | 'normative' | 'user-confirmed'
  scopes: string[]

  // ── 棘轮：这是整个回执模型的核心 ──
  change: {
    mode: 'import' | 'delta' | 'structured-merge'
    baseMemorySha256: string | null
  }

  validFor: {
    commitRange: { start: string; end: string } | null
    semver: { min: string; max: string } | null
    platforms: string[]
    environments: string[]
  }
  preconditions: string[]
  postconditions: string[]
  counterexamples: string[]    // 参与 applicability 判定

  evidence: Array<{
    kind: 'topic' | 'path' | 'symbol' | 'test' | 'commit' | 'document' | 'user-confirmation'
    locator: string
    path: string
    sha256: string
    fingerprint: string        // 16 hex，符号切片指纹
    symbol: string | null
  }>
  evidenceRootSha256: string   // sha256(排序后的 evidence 列表)

  verifier: { kind: 'machine' | 'reviewer' | 'user'; id: string }
  sourceCommit: string | null
  rollback: { previousReceiptId: string | null; previousMemorySha256: string | null }
}
```

### 7.1 链式不变量（`validateTrustLock`）

- 每条回执**自洽**：`receiptId` = 自身摘要、`evidenceRootSha256` = 证据摘要、
  `transition` 合法、`lifecycle === transition.to`
- 相邻两条：`from === previous.lifecycle`、
  `rollback.previousReceiptId === previous.receiptId`、
  `rollback.previousMemorySha256 === previous.memorySha256`
- **第一条必须是 `import` 且 `baseMemorySha256 === null`**
- **后续不得再 `import`**：`memory trust history cannot re-import active data`
- `baseMemorySha256 === previous.memorySha256`
- **`previous.lifecycle === 'active'` 时，`change.mode` 只能是 `delta` 或 `structured-merge`**

最后一条是整个信任模型的地基：

> 初始迁移可以**导入一次**；此后每一次变更都必须**指名前驱的内容哈希**，
> 且只能走 `delta` 或 `structured-merge`。**全量重新导入被拒绝。**

否则「重新签名」就成了洗白路径 —— 这正是 `symbol-not-a-definition` 那条规则要防的事。

### 7.2 分离原则（OwnMem `TECHNICAL.md:14-31`）

- 正文可以写「这条很可信」——**不算数**。
- 回执只能由 `verifier` 写；`verifier.kind === 'user'` 是最高权威。
- 回执被篡改 → `integrity: blocked`，**阻断注入**。
- **`integrity` 不是 `truth`。** 哈希对得上只证明「内容与回执一致」，
  不证明断言正确。所以三个判决**分开算**：
  `integrity`（回执完整）/ `live evidence validity`（证据还在）/ `action authority`（够不够格行动）。

### 7.3 证据漂移的两级严重度（全协议最值得抄的一条）

**blocking**（取消资格，不交付）：

| reason | 触发 |
|---|---|
| `hash-drift` | 内容绑定物被改（条目正文 / 权威文档 / 用户确认） |
| `unsafe-path` / `missing-path` | 路径不安全 / 不存在 |
| `symbol-missing` / `commit-missing` | 符号 / 提交消失 |
| `document-id-drift` / `document-not-authoritative` / `document-path-drift` / `document-missing` | 权威文档失去结构性质 |
| `catalog-missing` / `catalog-invalid` | 目录损坏 |
| `review-lock-missing` / `review-lock-invalid` | 审阅锁缺失/损坏 |
| `confirmation-missing` / `confirmation-not-human` / `confirmation-content-drift` | 用户确认失效 |
| `evidence-invalid` / `evidence-kind-unsupported` | 证据本身不合法 |

**advisory**（降级但**仍交付**）：

| reason | 触发 |
|---|---|
| `fingerprint-drift` / `coarse-drift` | 锚点还在、内容变了（**通常是重构**） |
| `symbol-not-a-definition` | 切片命中的是**调用点或注释**而非定义 |
| `document-content-drift` | 文档内容变了但结构还在 |
| `test-execution-failed` / `test-execution-stale` | 测试跑挂了 / 过期 |

> **把所有漂移都当攻击，会把每一次重构都变成隔离。**

`symbol-not-a-definition` 是这套分级的尖刀：锚点**可以稳定但错位** ——
一条教训说「这个符号不该存在」，却锚在说这句话的注释上。
指纹稳定、回执健康，但它在**给错的代码块背书**。**必须报出来，不能重新签名。**

实测：178 个锚点里 3 个是弱锚点；符号切片指纹的误报率 10.8%，整文件哈希 33.3%
（整文件哈希在无关编辑下就会漂）。

### 7.4 `integrity` 三档 → 交付

| integrity | 条件 | 交付 |
|---|---|---|
| `passed` | `valid && advisory_reasons.length === 0` | 正常 |
| `advisory` | `valid` 但有 advisory，**或**唯一 reason 是 `receipt-missing` | 仍交付，**信任块永不被压缩删除** |
| `blocked` | 其他 | **永不出现在 `results`，也永不出现在 `pointers`** |

`nominal` 判定：`lifecycle === 'active' && integrity === 'passed' && authority !== 'advisory'`。
缺省 trust 视为 nominal（老语料降级而非静默）。

## 8. 生命周期对交付的影响

两个正交轴，**都看**：

**轴一：`confidence`（可不可信）**

| `confidence` | 可注入 | 交付层级 |
|---|---|---|
| `verified` | ✅ | `content`（若分数够） |
| `inferred` | ✅ | `content` 或 `pointers` |
| `stale` | ✅ | **只给 `pointers`**（降级） |
| `deprecated` | ❌ | 不交付 |

**轴二：`lifecycle`（在不在活跃集里）** —— 状态机与合法迁移抄 OwnMem `memory-lifecycle.mjs:3-42`：

```ts
states = [observed, candidate, shadow, advisory, active, stale, deprecated, rejected, superseded]

transitions = {
  observed:  [candidate, rejected],
  candidate: [shadow, advisory, rejected],
  shadow:    [advisory, rejected],
  advisory:  [active, stale, deprecated, rejected, superseded],
  active:    [stale, deprecated, superseded],
  stale:     [advisory, active, deprecated, rejected, superseded],
  deprecated: [], rejected: [], superseded: [],        // 终态
}

injectable = state ∈ {advisory, active}                // memoryLifecycleInjectable
```

| 情形 | 判决 | 交付 |
|---|---|---|
| 回执被篡改 / 缺失 | `lifecycle = advisory`（缺回执）或 `blocked`（篡改） | `blocked` → `abstain(blocked-validity)` |
| `expiresAt` 已过 | 转 `stale` | `abstain(expired)` 并点名 |
| 证据目标消失 | `blocked` | `abstain(blocked-evidence)` |
| 目标还在但切片变了 | `advisory` | 仍交付，**标注什么动了** |
| 锚点落在注释/调用点 | `advisory`，`symbol-not-a-definition` | 交付但**不重新签名** |

**禁止的迁移立即抛错**（`assertMemoryLifecycleTransition`）：
终态不可逆，`deprecated → active` 这类必须走人工 `memory_resolve`。

## 9. 审计日志（`ledger.jsonl`）

每行一个 JSON 对象，**append-only**，永不删：

```jsonc
{"ts":"…","kind":"attempt","id":"…","decision":"accepted","gates":[...],"confidence":0.72}
{"ts":"…","kind":"attempt","id":"…","decision":"rejected","code":"secret","rule":3}
{"ts":"…","kind":"attempt","proposalId":"p_…","decision":"deferred","deferredBy":["G6"]}
{"ts":"…","kind":"resolve","proposalId":"p_…","action":"accept","by":"user","reason":"…"}
{"ts":"…","kind":"drift","id":"…","evidence":"src/x.ts:17","verdict":"advisory","moved":"symbol"}
```

**用途**：
1. 用户能回答「它到底自己记了什么」（自主度的可审计性）
2. `memory_audit` 据此算**拒答率 / 延迟率 / 漂移率**
3. 连续 DEFER 计数

**隐私**：G3 命中时正文脱敏；ledger 只记 `code` 与 `rule` 序号，不记命中内容。

## 10. 弱度（weakness）—— 只列，不选

G7 需要「最弱候选」。定义：

```ts
weakness(entry) =
    0.35 * (1 - confidenceScore(entry))
  + 0.25 * staleness(entry)              // 0..1，按 lastVerifiedAt 线性
  + 0.20 * (1 - evidenceStrength(entry)) // 证据越弱越该退
  + 0.10 * (1 - usageRate(entry))        // accessCount / 最大 accessCount
  + 0.10 * orphanRatio(entry)           // 关系边越少越孤立
```

**协议只用它排序，不用它做决定。** 退休谁是人点的事。

## 12. 版本与兼容

- 协议版本 `mrp: 1`，写进每个回执。
- 门是**只增**的：新增门要升版本；删门要保留 `deprecated` 占位，否则老回执无法重算。
- `Candidate` / `Receipt` 的字段**只增不删**；老条目缺新字段时按「未知」处理，
  不允许「默认值伪装成已知」。
