## 反触发（这些情况**不用**读文档）

| 情况 | 为什么不用 |
|---|---|
| 只想知道某个函数的签名 | 直接 `read` 源码，文档不保证同步 |
| 通用编程问题（语言特性、第三方库用法） | 与项目无关 |
| 已经知道要读哪个文件 | 直接读，跳过分发 |
| 想确认某个行为**现在**成不成立 | `npm test` 比文档可信 —— 文档写「应该」，测试写「确实」 |

## 三层信息密度

每篇文档都按 **结论优先 + 边界条件 + 指针** 组织。所以：

1. **先看前 30 行** —— 每篇开头都是结论表，够回答 80% 的问题。
2. **需要证据再往下翻** —— 正文的每个判断都附 `文件:行号`。
3. **不要通读** —— 这几份文档加起来超过 25 万字符，通读是负收益。

## 维护约定（CI 强制）

> 这一节由 `scripts/check.mjs` 硬门检查，**不是建议**。

1. 每个含 `.md` 的目录**必须**有 `README.md`，且必须**列全**该目录下的 `.md`。
2. 新增一篇文档 → 同一提交里给它补一行路由。
3. 删除/改名一篇文档 → 同一提交里清掉那一行。
4. 只做**一层**。不要在 `docs/` 下再开子目录配子索引 —— 对方的
   `design-index-first-architecture.md:191-202` 试过，然后退回到 `glob` 兜底：
   每多一层维护成本线性增长，而 `glob("docs/**/*.md")` 是零成本的。

违反 1–3 会让 `node scripts/check.mjs` 红；违反 4 不会被检查，但会被 review 打回。
