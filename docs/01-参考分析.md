# 参考分析：OwnMem 与 gingugu

> 本文只回答一个问题：**这两个库各自解决了什么、机制怎么做的、哪些该抄进 DSH 记忆插件、哪些不该抄。**
> 全部结论都对着源码/文档核对过，引用为 `仓库内路径:行`。

---

## 0. 结论先行

| | OwnMem | gingugu |
|---|---|---|
| 一句话 | **治理型记忆**：仓库即记忆，证据决定交付，人提交才算写入 | **系统型记忆**：一个本地 brain 服务所有宿主，带关系图、生命周期和主动拦截 |
| 第一性问题 | 「谁拥有项目知识？一条坏记忆能不能在改变 agent 行为之前被拦住？」 | 「AI 永远不忘：上下文、决策、教训跨会话/跨仓库/跨工具留存」 |
| 形态 | 单 npm 包 + 仓库内 `.ownmem/*.md` + 快照索引 | 本地 MCP server（SQLite 单文件）+ 8 个宿主钩子 + Web UI |
| 最值得抄 | ①写入门/证据回执 ②三级交付 ③净值零增长 | ①类型化关系图 ②生命周期(decay/dream) ③主动拦截(tripwire/X-ray) |

两者的共识，也是本插件的设计前提：

> **记忆系统的失败点不是「记得少」，而是「记得多但不敢据它行动」。**
> 所以真正要设计的是**判定**，不是**存储**。

---

## 1. 定位差异（决定架构取舍）

**OwnMem 是「仓库的资产」。**
`README.md:26` 把记忆放在仓库里的 Markdown，随 clone / review / rollback 与代码同行；
`docs/ARCHITECTURE.md:76-89` 明确写「No unattended writes」——没有协调器、没有晋升、没有候选队列，
`init`/`new`/`outcome` 都是人的入口，MCP server **只暴露 2 个只读工具**（`recall`、`read`）。

**gingugu 是「一个进程外的 brain」。**
`docs/product-spec.md:5-8` 定位为本地 MCP server，跨工具共享一个 SQLite 文件；
工具面有 **30+ 个 `memory_*` / `code_xray` / `board` / `credential_*`**（`product-spec.md:24-107`），
写、读、关系、整合、拦截、凭据全在一层。

**推论（对 DSH 插件）：**
- DSH 是一等公民运行时，不是第三方宿主 —— 不需要 MCP 那一层序列化/传输/令牌/远程 brain 的复杂度（gingugu 为此写了 `serve.py` / `remote.py` / `serve_tls.py` / `client_grants.py` / `proxy*.py` 等十几个模块）。
- 但 DSH 的插件是**进程内**的，能直接挂 `agent/turn-stopping`、`session/event`、
  `systemPrompt.context` —— 也就是说 gingugu 靠「8 个宿主钩子」做的事，
  在这里是**两个事件监听器 + 一个 prompt context**。
- 记忆的物理位置仍应学 OwnMem：**仓库内可 review 的 Markdown 为权威副本**，索引是可重建的派生物。

## 2. 记忆模型对照

### 2.1 OwnMem 的条目（`schemas/memory.schema.json`）

```jsonc
{
  "name": "staging_timeout_pool_cap",        // ^[a-z0-9]+(?:_[a-z0-9]+)*$
  "description": "…",                         // 1..1000，一行摘要
  "metadata": {
    "node_type": "memory",                    // 常量
    "type": "lesson|debug|preference|feedback|decision-pointer",
    "status": "active",
    "scopes": ["…"],  "applies_to": ["…"],  "triggers": ["…"],
    "last_verified": "YYYY-MM-DD",
    "expires_at": "YYYY-MM-DD|null",
    "review_by": "YYYY-MM-DD",                // preference/feedback 必填
    "authority": "observed|normative|user-confirmed",
    "authority_docs": [], "history_docs": [], "supersedes": [],
    "retired_by": "hook|ci|entry",
    "code_evidence": [ { "path": "…", "symbols": [], "tests": [], "commit": "…" } ],
    "evidence": ["…"],
    "originSessionId": "…", "created": "…", "modified": "…"
  }
}
```

关键设计：**`authority` 与 `evidence` 是条目自己声明的，但条目不能靠声明获得权威**——
`docs/ARCHITECTURE.md:35-58` 说明真正的信任在**条目之外**的 `trust.lock.json` 回执里，
绑定内容哈希、证据根、生命周期、适用性、行动风险、校验者身份、前序回执。

### 2.2 gingugu 的条目（`src/gingugu/models.py:139-202`）

```python
Memory(id, namespace_id, type: MemoryType, title, content,
       confidence: verified|inferred|stale|deprecated,
       source, created_at, updated_at, last_accessed, last_confirmed,
       access_count, metadata, pinned,
       provenance: user-asserted|measured|file-derived|self-concluded,
       about,            # 「这条记忆是干什么用的」，进 FTS5 和 embedding
       tags[])           # 来自 memory_tags 表
```

两个正交轴（`models.py:79-89` 注释）：

- `confidence` = **可不可信**（verified / inferred / stale / deprecated）
- `provenance` = **怎么信上的**（user-asserted / measured / file-derived / self-concluded）
  > 「a `verified` memory can still be `self-concluded`, and that is exactly the case this field exists to show.」

关系类型（`models.py:92-123`）：
`supersedes | related_to | caused_by | contradicts | parent_of | child_of`，
且 `related_to` 的检索权重是 **0**，方向性边才是 1 —— 「一条 `related_to` 是兜底，不是默认」。

### 2.2b 断言模型（gingugu 最值得抄的一件事）

一条说「PR #10 还开着」的记忆是在做**断言**。它写的时候为真，散文是诚实的历史，
**永不为了跟踪世界而改写**。没有这个原语时，唯一能记录「PR #10 已合并」的办法是
改写记忆或粘一条 `=== STATUS ===` 横幅 —— 而 dogfooding 语料因此长出了
**37 条记忆上的 160 种不同横幅风格**（`docs/architecture.md:895-898`）。

```sql
memory_claims (
  id, memory_id, kind, ref,        -- ref 是 repo 限定的，如 "gingugu#10"
  state,                           -- 记忆所断言的，永不改写：open | resolved | unverified
  evidence,                        -- 命中的窗口文本，≤200 字符
  resolved_state, resolved_by, resolved_at,   -- 后来学到的，另存
  UNIQUE (memory_id, kind, ref)
)
```

这条设计把「记忆会过时」这个无解问题，变成了**可枚举、可对账、可矛盾检测的结构化积压**，
代价只是两张窄表。三个被语料打出来的细节：

| 细节 | 实测 | 为什么 |
|---|---|---|
| **无状态 ref ≠ open** | 1,161 条记忆里 225 条 ref 无断言状态，对 223 条真 claim；且绝大多数在叙述**已完成**的工作（`"Fixed in PR #873"`） | 默认成 open 会把积压翻倍，全是历史。→ 独立状态 `unverified`，**是索引不是队列** |
| **引用不是断言** | 785 条语料上 11 条 claim 来自 wiki-link 内部，**每一条都错** | `[[PR #10 open: …]]` 是指向同名记忆的**链接**。→ 抽取前抹空 wiki-link span |
| **`shipped` 不算 resolved** | `"merge HELD"` 同时含两边的词 | 漏一条 claim 静默无害；猜错一条会教读者彻底忽略 claims |

**`sync_claims` vs `rederive_claims` 的关键区分**（`.ai/standards/02-database.md:52-67`）：

| | 何时 | 对 resolution 做什么 |
|---|---|---|
| `sync_claims` | 记忆的**散文变了** | **丢弃** resolution —— 散文动了，它断言的东西可能也动了，陈旧的解析指针比没有更糟 |
| `rederive_claims` | **抽取器变聪明了**，文本未变 | **保留** resolution，只删当前抽取器不再推导的行 |

### 2.3 统一模型（本插件采用）

两个模型可以拼成一个，且**拼完之后比任何一个都更适合 DSH**：

```ts
interface MemoryEntry {
  // 身份
  id: string                    // ownmem 的 name 规则：snake_case，全局唯一键
  title: string                 // 一行
  kind: 'decision' | 'pitfall' | 'convention' | 'correction' | 'fact' | 'capability'
                                //      ↑ 收敛 ownmem 的 5 类 + gingugu 的 9 类

  // 内容
  body: string                  // Markdown 正文（模板由协议约束）
  about: string                 // gingugu 的「干什么用的」，进索引与 embedding

  // 判定（两条轴都不许省）
  confidence: 'verified' | 'inferred' | 'stale' | 'deprecated'      // 可不可信
  provenance: 'user-asserted' | 'measured' | 'file-derived' | 'self-concluded'  // 怎么信上的

  // 证据（ownmem 的核心）
  evidence: Array<{
    kind: 'file' | 'symbol' | 'test' | 'commit' | 'command' | 'doc' | 'user'
    ref: string                 // repo-relative path / 符号 / 测试 id / sha / 命令
    hash?: string               // 内容哈希，用于漂移检测
    excerpt?: string
  }>

  // 断言（gingugu 的核心）—— 正文永不为跟踪世界而改写
  claims: Array<{
    kind: 'pr' | 'issue' | 'ticket' | 'branch' | 'dep' | 'status'
    ref: string                 // repo 限定，如 "acme/api#10"
    state: 'open' | 'resolved' | 'unverified'   // 写时断言，永不改写
    resolvedState?: string      // 后来学到的
    resolvedBy?: string         // 哪条记忆/哪次核对
    resolvedAt?: string
  }>

  // 生命周期
  scope: string[]               // 适用面（repo / 子目录 / 语言 / 环境）
  triggers: string[]            // 什么查询词/文件应唤起它
  createdAt: string;  modifiedAt: string
  lastVerifiedAt: string;  reviewBy?: string;  expiresAt?: string
  supersedes: string[]          // 被本条目取代的 id
  relations: Array<{ type: RelationType; target: string }>
  pinned?: boolean              // 常驻 tier，免排序

  // 治理
  status: LifecycleState
  //   observed → candidate → shadow → advisory → active
  //                              ↘ stale → deprecated | rejected | superseded
  //   （状态机与合法迁移抄 ownmem `lib/memory-lifecycle.mjs:3-42`；
  //     `deprecated/rejected/superseded` 是终态，不可逆）
  actionRisk: 'R1' | 'R2' | 'R3' | 'R4' | 'R5'   // 见 §4.4
  trust: TrustReceipt           // 与正文分离存放，正文不能自证
}

interface TrustReceipt {
  contentHash: string
  evidenceRoot: string
  lifecycle: string
  applicability: string
  actionRisk: 'low' | 'medium' | 'high'
  verifier: { kind: 'gate' | 'user' | 'host'; id: string }
  predecessor?: string          // 前序回执，用于 rollback 链
}
```

**为什么必须分开存**：OwnMem `docs/TECHNICAL.md:16-31` 讲得很清楚——
「完整性不等同于真实性：哈希对得上只证明内容与回执一致，不证明断言正确」。
所以 `receipt integrity`、`live evidence validity`、`action authority` 是**三个独立判据**。

## 3. 召回管线对照

### 3.1 OwnMem：5 路 + RRF + 4 门 + 3 级

**融合**（`lib/memory-compiler.mjs:671-674`）：

```js
rrf: { k: 10, channel_weights: { exact: 8, bm25f: 16, ngram: 0.1, fuzzy: 0.25, graph: 0.05, embedding: 0 } }
```

- `embedding` 权重**默认 0**，只有在仓库本地 A/B 证据过安全门之后才允许并入
  （`docs/TECHNICAL.md:176-179`）——「可选通道从 observation 模式起步」。
- `bm25.k1 = 1.2`；字段权重 `MEMORY_FIELD_CONFIG` 带长度归一与 exact boost。

**打分特征**（`memory-compiler.mjs:675-697`）：

```js
features.weights = {
  exact_anchor: .15, approximate_anchor: 0, embedding_similarity: 0,
  query_coverage: .2, query_span_coverage: 0,      // ← 门用，不用来排序
  matched_terms: .15, high_signal_concepts: .3, high_signal_terms: .15,
  anchor_terms: .15, field_coverage: .2,
  scope_overlap: .01, authority: .01, evidence: .01, freshness: .01,
  graph_quality: .02, channel_diversity: .05,
}
```

注意 `authority/evidence/freshness` 只有 0.01 —— **权威不是靠加分买来的，是靠门禁**。

**四道独立的门**（`docs/TECHNICAL.md:89-105`）：
relevance、epistemic validity、task applicability、action risk。
任何一道拒绝都会**点名是它拒的**，而不是塌成一句「没匹配上」。

**三级交付**（`docs/TECHNICAL.md:48-78`）：

| 层级 | 条件 | 交付物 |
|---|---|---|
| `content` | 最高分 ≥ 阈值 **且** 覆盖率 ≥ `coverage_floor` | 记忆原文 + 出处 |
| `pointers` | 有合格候选但不到阈值 | 最多 3 条「标题 + 一行 + 打开命令」，**明确不是答案** |
| `abstain` | 无合格候选 | 空 + **不给答案的原因** |

阈值按查询类型分档（`memory-compiler.mjs:735-742`）：
`identifier .6 / path .7 / error .7 / natural .65 / decision .65 / mixed .65`
另外 `coverage_floor = 0.45`（`memory-compiler.mjs:772`，附大段实测说明为什么是这个值、
以及它在多语言形态学上的代价），MMR `lambda .78 / similarity_threshold .82`。

**content 档还有第二个常量**（`lib/memory-runtime-contract.mjs:69,86`）：

```js
MEMORY_CONTENT_TIER_THRESHOLD        = 0.85   // 消融曲线拐点：0.80→13 条仍交付、0.85→2、0.92→0
MEMORY_EXACT_ANCHOR_CONTENT_STRENGTH = 0.5    // 单 token 查询 gate 分数中位 0.840，
                                              // 用 0.85 会把 8/15 个精确符号查询踢到 pointer 档

contentTier = top != null
  && candidateExplainsQuery(top, natural, coverage_floor)
  && (top.gate_score >= 0.85
      || (!natural && top.features.exact_anchor >= 0.5))
```

> 一个诚实的坏消息数字（`memory-context-budgeter.mjs:451-460`）：
> `gate_score` 在 336 条 content 交付上 AUC **0.812**，去掉 223 条 self-proving smoke 后
> 只剩 **0.667**；同一批 `query_span_coverage` 到 **0.886**。
> —— 置信分数回答的是「ranker 有多确定」，不是「这条记忆解释了多少问题」；两者必须都过。

**abstain 的 10 种原因**（`schemas/protocol/query-result.schema.json`）——**弃权必须带原因**：

```
no-trusted-candidate    below-threshold         below-coverage
blocked-validity        blocked-applicability   blocked-risk
budget-empty            all-candidates-excluded below-content-threshold
```

门只有六个：`null | relevance | validity | applicability | risk | budget`。
`below-content-threshold` 与 `no-trusted-candidate` 要求的动作**相反**
（一个是「找到了但压下」，一个是「语料里没有」），塌成一句「没匹配上」等于丢掉这个区分。

**exact channel 的 kind 分数**（`memory-query-planner.mjs:51-62`，与 feature 层不同）：
`name 12 / trigger 7 / path 14 / basename 11 / symbol 15 / symbol-suffix 12 /
test 12 / test-case 13 / doc-id 10 / error 14` —— 同一文档多个锚点**累加**。

**token 压缩阶梯共 17 级**（`memory-context-budgeter.mjs:394-447`），
顺序即「最便宜的损失先付」，从删三个 hex 摘要（agent 无法验证、审计者本机有 receipt store）
一路到删 `logical_type`。**一条不变量**：

> **nominal 的 trust 块可以删；非 nominal 的永不可删。**

否则同一条记忆会因降级路径不同而带不同标签。实测：v4 瘦身后 envelope 固定元数据
从 ~433 降到 309 token，留给引文的预算从 ~36 提到 ~91；「无引文 envelope」从 92 中 39 条降到 0 条。

**为什么要有 pointers 这一级**（`docs/TECHNICAL.md:191-207`）：
两级的协议会逼所有边界情况二选一，而「自信地引用」是两种错误里更便宜的那个，于是系统会对
它根本无话可说的问题给出确定的答案。pointers 层被**实测**过：单个 pointer 的特征 AUC 最好只到
0.66（引用门是 0.89），成本曲线没有拐点 —— 所以「不给 pointer 加门」本身是个**记录在案的结论**。

### 3.2 gingugu：混合检索 + pinned tier + 扩散激活

- `memory_recall`：BM25 + 语义混合，多命名空间 CSV，`explain=True` 给逐项 `score_breakdown`（`product-spec.md:29`）
- `memory_search`：精检 + 过滤（`claims="open"|"contradicted"|"unverified"`、`orphans=True`、`pinned=True|False`）（`product-spec.md:30`）
- `memory_context`：会话预热 + **扩散激活**，pinned tier 先加载且**加性**于 `limit`（`product-spec.md:31`）
- 关系类型加权（`models.py:110-123`）：方向性边权重 1，`related_to` 权重 0，「两条分档不是六条 ——
  没有实测说 `supersedes` 该排在 `caused_by` 之上，编造这个顺序等于把猜测写成排序规则」
- 空结果**加宽**：作用域查询无命中时扩展到全部命名空间并回 `widened_from`（`product-spec.md:29`）

**主动召回（involuntary recall）**（`product-spec.md:55`；常量见 `recall_gate.py`）：
`UserPromptSubmit` 钩子不靠 agent 决定就抛出记忆，**五道串行拒绝**：

```python
MIN_PROMPT_CHARS = 40        # 之下没有可检索主题："go", "lfg", "ship it"
DEFAULT_BAR      = 0.78      # 绝对 cosine 地板（噪声顶部 ~0.64，真信号从 ~0.73 起）
DEFAULT_MARGIN   = 0.15      # 相对自身扫描**中位数**的余量 —— 真正干活的 gate
MAX_INJECTED     = 3
```

- **`context` 类型被排除**：它绝大多数是会话反思，用与用户打字相同的交谈语域书写，
  所以按**情感**而非**主题**匹配 —— 在成熟个人 namespace 里它们表现得像语义捕蝇纸。
- **相对余量才是核心**：一个命中必须比**它自己那次扫描的中位相似度**高 0.15。
  它是相对的，所以能适应「这个提示词根本没有独到匹配」—— 当一切都得分相仿时，
  **什么都点不亮，不管绝对分数漂多高**。
- **词法半边是「要求」而非「排序器」**（`LEXICAL_POOL = 60`，宽松）：同时要求两半，
  才是让 gate 要求主题重叠而不是满足于共享语气的关键 —— **测到的最大单项精度增益**。
- **中位数必须来自完整扫描，不能取预裁的 top-N**：在已过滤的头上取中位数，
  描述的是赢家而不是它们击败的场地。
- **会话内抑制**（TTL 7 天）：没有它，一条匹配某个话题的记忆会在每一轮重新浮现 ——
  一个未被请求的信号就这样变成口吃，并训练读者完全跳过这一块。

实测：548 条真实提示词 / 951 条记忆的 brain，**5% 的轮次触发，平均 1.58 条，
26 次触发中只有 4 次撞 cap**。最后这个数字才是重要的：
> **一个永远只在截断更大集合的阈值不是选择，它是用完了空间。**

**`memory_context` 的两个反直觉决定**：

1. **recency 桶必须按 `updated_at` 而非 `last_accessed` 排序**。这个桶存在的目的是让
   一条**刚写下、从未被读过**的记忆活过截断。按读时间戳排，等于用「我最近见过它吗」
   回答「这对我新吗」—— 两者按定义反相关。更糟的是 `memory_context` 自身会 touch
   它展示的一切，于是每次加载都把自己的输出提升进下一次加载的桶，**桶收敛到它已经展示过的东西**。
2. **选择顺序 ≠ 呈现顺序**。配额填充是**生存**问题（recency 优先），
   呈现是**可比性**问题（桶内原生序）。把两者混为一谈，就会出现「被保证的 recency 槽位
   在长 payload 尾部」这种既不满足配额也不满足阅读的失败。

**性能陷阱（值得贴墙）**：
`SEMANTIC_COHORT = 40` 与 `ENTRANT_CAP = 5` 曾经是 `limit * 4` / `limit // 2`，
导致同一条记忆在同一条 query 上，**仅因 `limit` 不同**而得分
`0.9439 / 0.9379 / 0.9245 / 0.9172`。

> **把问题问得更精确的调用者，得到了不同且更差的答案。**

排序 key 用 `(-score, id)` 断平局，不用迭代顺序：精确同分极常见（RRF 把相同 rank pair
映到相同浮点数），而遍历 `set` 会让两条同分记忆的先后**因进程而异地飘**。

### 3.3 对本插件的取舍

| 机制 | 决定 | 理由 |
|---|---|---|
| 5 路 + RRF(k=10) + 分档阈值 | **抄** | 确定性、零网络、可复现；DSH 是本地进程，没有理由付向量 API 的钱 |
| embedding 权重 0 起步 | **抄** | 默认不联网，A/B 过了再开 |
| 三级交付（content/pointers/abstain） | **抄，且是核心** | 直接回答「拿不准怎么办」：**拿不准就降级，不是硬答** |
| `coverage_floor` 双门 | **抄** | 置信分数与「解释了问题多少」是两件事 |
| 4 门独立 + 点名 | **抄（只做了 2 道）** | 拒绝要可归因。**只实现 relevance + budget**，epistemic / applicability / action-risk 未实现 |
| pinned 常驻 tier + 加性 | **抄（只抄了字段）** | 极少数「永远不能缺」的规则。**`pinned` / `expiresAt` 已进快照，召回过滤未接** |
| 扩散激活 | **改** | 先做 1 跳邻接，别一上来做 PageRank 排序 |
| 空结果加宽 | **抄** | 廉价的召回率提升 |
| MCP / 远程 brain / 令牌 / TLS | **丢** | 进程内插件不需要；DSH 的 `tools.register` 就是工具面 |
| Web UI（Explorer/3D brain） | **后置** | 先有 UI slot 面板（pending 裁决 + 健康），3D 不做 |

## 4. 写入与治理对照（本插件的重点）

### 4.1 OwnMem：把人放在写入路径上

`docs/ARCHITECTURE.md:76-89`：

> 没有协调器、没有晋升、没有候选队列、没有 tripwire。**每一次记忆变更都是人做的编辑并提交**；
> 包只负责测量、提议和拒绝；**没有任何排名变更能绕过评测 harness 落地**。

配套三件事：

1. **schema / quota / 近重复** 三道审计（`docs/MEMORY_INSTRUCTIONS.md:6`）
2. **净值零增长**：活跃语料有硬条目数上限，**只减不增**；`ownmem audit` 在超限时失败，
   于是「往满的语料里加一条」必须同时「退休一条」（`docs/TECHNICAL.md:226-234`）。

   机制细节（`lib/memory-audit.mjs:118-156`，`quota.lock.json` schema `ownmem.quota/v3`）：
   语料先处在 `mode: 'growth'`；活跃条目达到 `growth_threshold = 50` 时**一次性切到 `ratchet`**，
   `max_active_l3` 锁成当时的条目数。此后：
   - `audit --write-lock` 时 `activeCount > maxActive` → error `quota-ratchet-raise`（**只降不升**）；
   - 只读时超限 → error `quota-topic-count`。

   > 「一个每次加条目就被抬高的字节预算从来没有拒绝过任何东西，它只是增加了文书工作。」
   >
   > 这个字节上限**七周被手工抬高六次**，然后被删掉（`memory-swap-nomination.mjs:1-13`）。

   配额打满时给**最弱候选**（`nominateSwapOut`，`:134-181`），只提名不删除：
   入链 ≥2 的 hub 直接排除；排序 `never-delivered` 优先 → 天数降序 → 证据数升序 → 字节降序。
   无遥测时输出 **`no retained telemetry — delivery is unknown, not zero`**
   —— 不许把「未交付」读成「从未使用」。

3. **近重复双阈值合取**（`lib/memory-duplicates.mjs:7-13`）：
   `simhash_similarity >= 0.84 && minhash_similarity >= 0.72`，指纹文本先**剥离代码块**。
   只 warning 不阻断 —— 重复是人的判断。

4. **三本账，绝不互相替代**（`docs/TECHNICAL.md:181-222`）：

   | # | 面 | 允许说的话 |
   |---|---|---|
   | 1 | `recall-feedback.jsonl`（`correct / correct_abstain / wrong / retrieval_miss / coverage_gap / stale / conflict`） | 「召回有没有返回对的东西」 |
   | 2 | `outcome-receipts.jsonl`（`applied / helpful_but_not_used / harmful`，只能 user 或 host 确认） | 唯一能谈「实际被应用」的面 |
   | 3 | `attribution.jsonl`（`basis: self-attribution`） | **只报计数，永不报 rate** |

   头条指标是 **known false-delivery residual**：分母是「至少有一条 `wrong` 回执报告过**有交付**」的
   去重 query 集合 —— 打在弃权上的 `wrong` 是抱怨「沉默」而不是「交付」，进分母会让
   残留率随检索变好而**上升**。

   还有一条纪律值得抄：`quality.feedback.accuracy_measurable = false`，原因是**结构性的**
   （「一次错误召回不留行为痕迹，所以 `wrong` 没有来源，分母无法成形」），
   而不是「暂无数据」—— 后者承诺一个会到达的数字。

5. **评测 harness 的切分单元是「topic 连通分量」**（`memory-evaluation-cases.mjs:927-1033`）：
   共享任一 expected topic 的 case 永不跨 tuning/holdout，否则同义词会漏进 holdout；
   `split.method` 与 `split.seed = 20260919` 记进 `quality.lock.json`，**只许扩、不许重切**
   —— 重切就是「为好看的 holdout 而挑选」。
   泄漏门 `0.6`（对 triggers/description/body 前 1200 字**逐字段**取最大，
   不对整篇 body 求 Jaccard，否则两 token 的 identifier 会躲在长 debug lesson 后面）。
3. **证据漂移降级**（`docs/ARCHITECTURE.md:49-53`）：
   - 回执被篡改 / 内容未 review / 证据目标消失 / 条目过期 → **quarantine（阻断注入）**
   - 目标还在但**符号切片变了**（多半是重构）→ 降为 **advisory**，并**报告什么动了**

   还有更尖的一种：`docs/TECHNICAL.md:33-39` 的 `symbol-not-a-definition` ——
   锚点落在一句注释或调用点而不是定义上时，指纹是稳定的、回执是「健康」的，但它**在给错的代码块背书**。
   最锋利的例子：一条教训说「这个符号不该存在」，却锚在说这句话的注释上。
   **这种形态必须报出来，不能靠重新签名糊过去**（重新签只是又签了一遍注释）。

### 4.2 gingugu：把「不确定」做成显式的

- **写时提示**（`product-spec.md:49-51`）：store 时返回 `similar` / `suggested_relations`，
  但两者的门是 **cosine（无 embedding 时 token Jaccard）**，报 `similarity` + `basis` 而不是 `score`；
  无关 payload 返回**空列表**而不是三个候选。
- **关系纪律**（`product-spec.md:51`）：`supersedes / contradicts / caused_by / parent_of` 优先，
  `related_to` 是兜底。
- **重写即确认**（`product-spec.md:81`）：`memory_update` 标题或正文**真的变了**才推进 `last_confirmed`；
  改类型/标签/元数据不算。
- **簿记不是新鲜度**（`product-spec.md:82`）：`updated_at` 只在存储字段**值变化**时动。
- **破坏性工具走客户端确认**（`product-spec.md:104`）：
  硬删、级联删命名空间、`keep_originals=False` 的整合、会覆盖 id 的导入、`credential_delete`
  —— 都通过 MCP elicitation 问用户，**且答案是一个不在 input schema 里的隐藏参数**，
  「所以模型无法提供它」。无对话框的客户端算「不能问」，给出结构化拒绝并指向 CLI。
- **tripwire**（`product-spec.md:56`）：一条记忆可以挂一个显式触发器，
  在匹配的工具调用**之前**把它拦下来一次，理由就是那条记忆。**同一个调用原样重发就放行**
  —— 这是「提醒」而不是「墙」。`mcp__gingugu__*` 永不触发，保证坏 tripwire 永远能修。
- **minion fence**（`product-spec.md:102`）：子代理内禁止碰 brain 数据目录、禁止再 spawn，
  「防事故，不防同用户恶意进程」。

### 4.3 本插件要补的那一块

两个库都**没有**正面回答用户的问题：

> 「有比较强的自主能力，知道自己什么时候该记、什么时候不该记；但也能够手动调用；
> 每个过程让 AI Agent 自己去审核，根据协议去调用，审核不通过之后再返给用户去判断；
> 拿不准的话，也要让用户有足够强的掌控能力。」

- OwnMem 的答案是**彻底放弃自主**（人提交才算写入）。
- gingugu 的答案是**把自主藏在工具面后面**（模型自己决定调 `memory_store`），
  再把「不确定」外化成 elicitation 弹窗。

本插件的答案是第三条路：**把「该不该记」写成一个可执行的判定协议，
由宿主侧强制执行、由模型侧主动申报，协议自己给出三值裁决，
只有它自己判不了的时候才交给人。**

### 4.4 行动风险与提示注入（OwnMem 最锋利的一块）

**风险等级不看记忆「在谈什么」，看「照它做能影响什么」**（`docs/TECHNICAL.md:97-105`）：

```js
// lib/memory-lifecycle.mjs:94-101
memoryContentActionRisk(record):
  R5: 破坏性动作 ∧ 安全域        // 「删除凭据」
  R4: 破坏性动作 ∨ 外部动作      // 「发布」「部署」「清空」
  R3: 安全域                     // 「密钥」「权限」「鉴权」
  R2: type ∈ {preference, feedback}
  R1: 其余
```

词表（`memory-lifecycle.mjs:44-46`）中英双语，且**记忆不能在自己的正文里声明一个更低的等级**
（`TECHNICAL.md:100`）。

**提示注入检测**（`memory-lifecycle.mjs:48-68`）——这段注释值得整段抄进设计：

> 这个模式是**故意窄**的：信号是「针对宿主指令层的祈使句」，不是两个常用词的共现。
> 上一版接受 `system|developer|instruction|policy|safety` 中任意一个，中文分支接受「规则」「安全」，
> 两者都是工程散文的日常词汇 —— 实测在 356 条语料上**永久屏蔽了 4 条记忆，一次真攻击也没抓到**：
> 包括描述这条防御本身的记忆、一条说 JSON 解码器忽略未知键的笔记、以及两次普通的「覆盖」用法。
>
> 所以现在两半都要求三段相邻：**动词 + 被寻址的层（system/developer/user）+ 它命名的产物（instruction/prompt/message）**。
> **精确性是靠匹配器买来的，不是靠软化后果** —— 与证据漂移不同，
> 一条指挥宿主的记忆是可能的投毒，爆炸半径是**提权**而不是过时建议，所以它保持硬阻断。

同一条匹配器**也读查询**（`memoryTextOverridesInstructions`）：
> 「记忆正文从来不是覆盖的唯一入口；在把它应用到两个面之前，直接敲进查询的注入会被当成普通自然语言评分。」

**这三个决定我全抄**：

1. 风险等级来自**变更面**，不来自自述
2. 注入用**高精度窄匹配**，宁可漏报
3. 同一个匹配器同时读**正文与查询**，两个面不能漂移成两种定义

## 5. 生命周期对照

| 机制 | OwnMem | gingugu | 本插件 |
|---|---|---|---|
| 衰减 | `expires_at` / `review_by` / `retired_by` | `decay.py` + 休眠（dormancy）生命周期 | 抄 gingugu：按 `lastVerifiedAt` + `accessCount` 的衰减，落到 `confidence: stale` |
| 过期 | 过期条目**不可注入** | `confidence: stale/deprecated` | 抄：`expired` 直接 abstain 并说明 |
| 整合 | 无（明确不做自动化） | `memory_dream`：PageRank + 标签传播 + 孤儿重连，**只产出提案队列**，`accept/reject` 由人点 | 抄：整合只出提案，绝不自动合并 |
| 去重 | 近重复审计 | `memory_consolidate` 的 suggest 扫描 | 抄 |
| 回滚 | 快照指针保留上一版活跃集 | `supersedes` 链 | 抄 ownmem：内容寻址快照 + 上一版指针 |

**dream 的纪律值得单独记**（`product-spec.md:40`）：

> 「pass 里没有任何东西写 `memories` 或 `relations`；一个 `accept` 如果要求一段算术拒绝做出的判断
> （一条边的 relation type、一个簇的名字），**它就被拒绝而不是给默认值**。」

这条纪律要照抄：**自动化只能提议它真的算得出来的东西，不能替人做选择。**

## 7. 可复用清单（终版）

### 直接抄

1. **仓库内 Markdown 为权威副本**，索引是可重建派生物（OwnMem `ARCHITECTURE.md:8-31`）

10. **dream 只出提案，不替人做选择**
11. **破坏性操作走用户确认，且答案不在模型可填的参数里**

## 8. 对 DSH 插件的直接结论

1. **记忆的物理形态**：`<workspace>/.dsh-memory/` 下的 Markdown + `trust/` + `pending/` + `ledger.jsonl`；
   **本插件不做全局层** —— 跨项目那一层由别的插件负责，这里只产出口（`lib/promote.js`）。
2. **召回发生在 `ctx.systemPrompt.context`**（`order: 130`，每轮装配），按 token 预算注入，
   三级交付，abstain 也要说话。**没有 `agent/pre-step` 监听器。**
3. **写入发生在 `agent/turn-stopping` 与显式工具调用**；两者都走**同一条审核协议**。
   写入**不在**召回路径上。
4. **「该不该记」是一个独立于「记得对不对」的判定**——
   OwnMem 的 `MEMORY_INSTRUCTIONS.md:5` 给了雏形：
   > 「当被要求记住某事时，先判断是不是由机器门、项目规则、权威文档、临时工作包或回归测试拥有它。
   > 只有在都不合适时才创建长期记忆。」
   本插件把这句话变成 **G1 归属门**。
5. **裁决是三值的**：`ACCEPT` / `REJECT`（协议说不，告诉模型怎么改）/ `DEFER`（协议判不了，交人）。
   —— 这是用户那句「审核不通过之后再返给用户去判断」的精确形式。
